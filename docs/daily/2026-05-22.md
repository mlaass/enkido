## cedar/

**Poly callback — Phases 1–4** (42c5271e, ebb54e47, 20398386)
- Expanded the per-voice field bank to all 11 event fields (`freq`, `vel`, `trig`, `gate`, `type`, `note`, `dur`, `chance`, `time`, `phase`, `sample_id`); `PolyVoice` snapshots event scalars at allocate time; chord events carry a per-voice `notes[]` array
- Phase 3: `prop_set_mask` bitmask on `Event`/`OutputEvent`/`PolyVoice` enables custom record-suffix fields per voice; config travels codegen→VM via `StateInitData::poly_prop_count`/`poly_prop_defaults`; `run_voice_pool` fills bank slots 11..11+prop_count
- **Legato gate-hold fix** (`dsp_state.hpp`): `allocate_voice` was setting `pending_gate_on` unconditionally for both mono and legato, causing legato to re-attack on every note; now computes `legato_hold = (mode==2) && was_active && !was_releasing` and skips the gate edge when held
- New tests: `test_poly.cpp` phases 1–4 (178→292 cases); `test_seqpat_step.cpp` (new file, 3 cases)

**fix(seqpat)** (9f36b29e)
- Rest-as-first-event no longer emits a spurious `.trig` pulse on cycle wrap; the cycle-wrap fallback in `op_seqpat_step` now checks `num_values > 0` before firing (matching the existing loop guard)

**SEQPAT_VALUES opcode + DynArray** (0e460da4, 557b7b2c)
- New `SEQPAT_VALUES` opcode packs the active chord's notes into a buffer (rate 0 = Hz, rate 1 = MIDI); `SEQPAT_FIELD` gains a `num_values` selector (rate 5) for runtime chord length
- `DynArrayPayload`: packed data buffer + per-block length buffer, consumable by `ARRAY_INDEX`; `len()` is now polymorphic (static arrays → `PUSH_CONST`, dynamic arrays → the len_buffer signal)
