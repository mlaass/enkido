## cedar/

**Files touched:** 8 | +395 insertions

- `feat(cedar): HOST_OP dispatch + host opcode registry` (`777ad3f`)  
  Adds a single `HOST_OP` opcode (slot 209) that dispatches through a 256-entry
  `HostOpRegistry` indexed by `inst.rate`, making host extensibility cost one
  enum slot regardless of registration count. Per-instance state is
  arena-backed (`HostOpState`) rather than inlined into the `DSPState` variant,
  with a `release()` hook picked up by the existing `HasArenaRelease` sweep.
  All new code is gated behind `CEDAR_HOST_EXTENSIONS` (default OFF);
  full suite passes 345/0 with the flag off. Five new test cases cover
  dispatch, collision rejection, safe unbound-index no-op, arena-state
  persistence, and hot-swap pooling (100 swaps → 1 instantiation).

  New files: `cedar/include/cedar/vm/host_op_registry.hpp`,
  `cedar/include/cedar/opcodes/dsp_state.hpp` (HostOpState variant),
  `cedar/src/vm/host_op_registry.cpp`, `cedar/tests/test_host_op.cpp`.

## akkado/

**Files touched:** 13 | +975 insertions

- `feat(akkado): host extension registration + hosted-node manifest` (`00b0c6b`)  
  Implements Phases 1–3 of `prd-host-extension-api` on the Akkado side, plus
  `register_host_node` (resolving studio-hosting PRD OQ12):

  - **`register_host_variable`**: control-rate host signals desugared onto the
    `ENV_GET` path, exposed via `host_variable_env_key()`; audio-rate rejected
    at registration.
  - **`register_host_function`**: a null `impl_fn` aliases a core opcode;
    a real `impl_fn` becomes a `HOST_OP`. Lookup falls through to the host
    registry only on miss, so core names are always authoritative.
  - **`register_host_node`**: heavyweight plugin instances named without
    widening `HOST_OP`. A string-literal parameter slot carries the node name
    (inputs[] slot = 0xFFFF, no instruction-layout change); compile result
    records `required_host_nodes {state_id, host_index, name}`, mirroring
    `RequiredMidiSource`.

  Collisions with core builtins/aliases/variables or earlier host registrations
  are rejected. Registry-owned strings back synthesized `BuiltinInfo`
  string_views for the process lifetime. Everything behind
  `CEDAR_HOST_EXTENSIONS`; suites pass 350/0 (cedar) and 1233/0 (akkado)
  with flag ON, 345/0 and 1223/0 with flag OFF. Three 300 s fixtures produce
  bit-identical WAVs in both builds.

  New files: `akkado/include/akkado/host_extensions.hpp`,
  `akkado/src/host_extensions.cpp`, `akkado/tests/test_host_extensions.cpp`.
