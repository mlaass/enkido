## cedar/ — 4 files touched

- **fix(cedar): reclaim SequenceState arena blocks on hot-swap re-init** (`state_pool.hpp`, `test_arena_reclaim.cpp`)
  `init_sequence_program` and `init_event_transform` were leaking arena blocks on every hot-swap recompile. The orphaned blocks accumulated until the 32 MB AudioArena was exhausted; drift fuzz at 100k iters hit 3,590 failed allocations. Fixed by releasing old sequence/event/output blocks before re-allocating; regression test asserts the arena bump high-water plateaus across 100 re-inits. Arena peak drops from 32 MB (full) to ~8.6 MB. Fixes #3.

- **fix: BufferPool::get out-of-bounds guard with VM dispatch breadcrumb** (`buffer_pool.hpp`, `vm.cpp`)
  Added as part of the void-arg fix (see akkado/ below): the guard now logs the offending instruction (opcode + inputs) via a `thread_local` breadcrumb set in the VM dispatch loop, and asserts in debug/sanitize builds so unwired-input paths fail loudly in CI.

## akkado/ — 2 files touched

- **fix(akkado): coerce void args to BUFFER_ZERO + W161 warning** (`codegen.cpp`, `test_codegen.cpp`)
  Piping onward from `out()` (which returns Void) wired the `TypedValue`'s 0xFFFF sentinel directly into the next builtin's input slot, causing `BufferPool::get(65535)` to be called 17k+ times per 100k drift-fuzz run. Codegen now coerces Void at a builtin slot (and Void operands on raw BinaryOp) to `BUFFER_ZERO` with a new W161 warning, consistent with the live-coding coerce-don't-fail philosophy. The E160 type check was explicitly skipping Void — that gap is now covered. Regression test verifies the three fuzz-reduced sources compile with `BUFFER_ZERO` on input 0 and W161 emitted. Fixes #4.
