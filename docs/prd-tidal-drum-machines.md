> **Status: IMPLEMENTED** — The drum machines of `geikha/tidal-drum-machines` (72 at the pinned commit) are available as built-in, auto-resolving banks. Samples stream from GitHub on demand (web) or via a local download script (CLI); nothing is bundled into the webapp deployment.

# PRD: Tidal Drum Machines — Built-in Catalog, On-Demand Samples

## Executive Summary

`geikha/tidal-drum-machines` is a well-known library of 80 vintage drum-machine sample sets (TR-808/909/606, LinnDrum, MPC60, Oberheim DMX, …). We want NKIDO users to reach those sounds with no setup: writing `pat("bd sd hh").bank("RolandTR808")` should Just Work.

The complication: the upstream repo is built for SuperDirt/Tidal and ships **no manifest**. It is 80 `machines/<Machine>/<machine-drumtype>/*.wav` folders and nothing else. NKIDO's bank loader needs a Strudel-style manifest to map drum names (`bd`, `sd`, `hh`, …) to files. This PRD bridges that gap.

Key design decisions:

- **One build-time generator** (`scripts/generate-tdm-catalog.sh`, bash + `git clone`) walks the upstream repo and emits **a single combined catalog JSON**, pinned to a commit SHA. The catalog is committed to NKIDO — it is text (~0.5–1 MB), not audio.
- The catalog is a **built-in catalog**: both the web app and `nkido-cli` register all 80 machines as known banks at startup, so `.bank("RolandTR808")` **auto-resolves** with no explicit load step.
- **Audio is never bundled.** The web app streams each required sample from `raw.githubusercontent.com` on demand (cached in IndexedDB). `nkido-cli` streams the same way, or reads from a local cache populated by `scripts/download-tdm.sh`.
- The existing bundled default kit (`bpb_808_clean`, 6.7 MB) **stays bundled** as the zero-network default; tidal-drum-machines is purely additive.
- A failed sample fetch is a **soft failure**: warn, that one sample is silent, the rest of the program keeps running.

## 1. Current State / Problem Statement

### 1.1 What exists today

NKIDO already has the full sample-bank machinery:

| Capability | Where | Notes |
|---|---|---|
| Strudel-format bank manifests (`strudel.json`) | `web/src/lib/audio/bank-registry.ts`, `tools/nkido-cli/asset_loader.cpp` | `bd → ["kick.wav", …]` variant arrays |
| URI resolution (`https:`, `github:`, `file://`, …) | `cedar/include/cedar/io/uri_resolver.hpp`, `web/src/lib/io/uri-resolver.ts` | `github:user/repo/path` → `raw.githubusercontent.com` |
| Sample fetch + decode + register | `audio.svelte.ts` (web), `program_loader.cpp` (CLI) | WAV/OGG/FLAC/MP3 decoded in WASM/C++ |
| IndexedDB cache | `web/src/lib/io/file-cache.ts` | 500 MB LRU, pinned entries survive eviction |
| `.bank("Name")` qualifier on patterns | `akkado` codegen → `RequiredSample{bank, name, variant}` | bank is a free-form string, host-resolved |
| Bundled default kit auto-discovery | `find_default_bank_uri()` in `asset_loader.cpp:469` | walks up CWD for `web/static/samples/bpb_808_clean/strudel.json` |

### 1.2 The gap

`geikha/tidal-drum-machines` cannot be loaded by any of the above because it has **no `strudel.json`**. Its structure is purely directory-based:

```
machines/
  RolandTR808/
    rolandtr808-bd/   RolandTR808-BD.wav, RolandTR808-BD2.wav, …
    rolandtr808-sd/   …
    rolandtr808-hh/   …
  RolandTR909/  …
  LinnDrum/     …
  …  (80 machines total)
```

Sub-folders are named `<machine-lowercased>-<drumtype>`; the README's drum-type codes are `bd` (kick), `sd` (snare), `hh` (closed hat), `oh` (open hat), `cp` (clap), `perc` (other), with more codes appearing in practice.

Today a user who wants a TR-909 kick has no path: there is no manifest to feed `loadBank()` / `--bank`, and writing `samples("github:geikha/tidal-drum-machines")` fails for the same reason.

| | Current behavior | Desired behavior |
|---|---|---|
| `pat("bd").bank("RolandTR808")` | unknown bank | auto-resolves; TR-808 kick streams from GitHub |
| Webapp deploy size | only `bpb_808_clean` (6.7 MB) bundled | unchanged — tidal samples never bundled |
| Discovering machines | none | browsable catalog in the Files panel |
| CLI offline use of tidal kits | impossible | `scripts/download-tdm.sh` populates a local cache |

## 2. Goals and Non-Goals

### 2.1 Goals

- **G1** — `pat("…").bank("<Machine>")` auto-resolves for all 80 machines, in both the web app and `nkido-cli`, with no explicit load step.
- **G2** — Tidal-drum-machine audio is **never** added to the Netlify deployment; samples stream from GitHub on demand and are cached in IndexedDB.
- **G3** — A single committed catalog JSON, generated by a reproducible script pinned to an upstream commit SHA, is the one source of truth for both hosts.
- **G4** — The Files panel gains a browsable catalog of the 80 machines (sounds + variant counts) with a per-machine "Load" (prefetch) action.
- **G5** — `scripts/download-tdm.sh` downloads selected machines into a user cache dir for offline `nkido-cli` use, auto-discovered by the CLI.
- **G6** — A failed sample fetch never crashes or blocks playback (soft fail).

### 2.2 Non-Goals

- **Not** un-bundling `bpb_808_clean` — the default kit stays as-is (a separate concern; see `prd-sample-loading-before-playback.md` lineage if revisited).
- **Not** generic support for arbitrary manifest-less GitHub sample repos — this PRD handles `geikha/tidal-drum-machines` specifically. A general "scan any repo" loader is future work.
- **Not** audio preview/audition in the catalog UI — browse + load only (future PRD).
- **Not** automatic upstream-update detection — refreshing the catalog is a manual rerun of the generator.
- **Not** compiler-level bank-name validation/autocomplete — `.bank()` resolution stays host-side; the compiler is unchanged.

## 3. Target Experience

### 3.1 Akkado source — auto-resolving banks

```akkado
// TR-808 kick + snare + closed hat, streamed on demand from GitHub
pat("bd sd hh hh").bank("RolandTR808") as e
  |> sample(e.trig, 1, e) |> out(@, @)

// Mix machines per pattern
pat("bd ~ bd ~").bank("RolandTR909") |> sample(@.trig, 1, @) |> out(@, @)
pat("~ cp ~ cp").bank("LinnDrum")    |> sample(@.trig, 1, @) |> out(@, @)

// Variant selection works as usual
pat("bd:0 bd:3 bd:7").bank("OberheimDMX")
```

No `samples(...)` directive, no UI click required — the bank name is matched against the built-in catalog.

### 3.2 Web — Files panel catalog browser

The Files panel gains a "Drum Machines" section:

```
┌─ Files ─────────────────────────────────┐
│ Loaded samples                          │
│   bd  sd  hh  …            (bpb_808)     │
│                                          │
│ ▾ Drum Machines      [search: tr8___ ]   │
│   RolandTR808   bd·8 sd·4 hh·3 …  [Load] │
│   RolandTR909   bd·6 sd·5 oh·2 …  [Load] │
│   RolandTR606   …                 [Load] │
│   … 80 machines …                        │
└──────────────────────────────────────────┘
```

- Browsing shows each machine's available sounds and variant counts (read from the catalog — no network).
- **[Load]** prefetches every sample of that machine into the IndexedDB cache (pinned), so the kit works offline afterward. It does **not** edit the user's code.

### 3.3 CLI — offline download script

```bash
# Download specific machines into the user cache
./scripts/download-tdm.sh RolandTR808 RolandTR909 LinnDrum

# Or everything
./scripts/download-tdm.sh --all

# nkido-cli auto-discovers ~/.cache/nkido/tidal-drum-machines/ and uses local
# copies; falls back to GitHub for machines not yet downloaded.
./build/tools/nkido-cli/nkido-cli render song.ak --seconds 30 -o out.wav
```

## 4. Architecture / Technical Design

### 4.1 Data flow

```
                 ┌──────────────────────────┐
   build time →  │ scripts/generate-tdm-     │  git clone (pinned SHA)
                 │ catalog.sh                │──────────────┐
                 └────────────┬─────────────┘               ▼
                              │ writes          github.com/geikha/
                              ▼                 tidal-drum-machines
   web/static/samples/tidal-drum-machines/catalog.json  (committed, ~0.5–1 MB)
                              │
            ┌─────────────────┴───────────────────┐
            ▼                                     ▼
   WEB host (audio.svelte.ts)            CLI host (program_loader.cpp)
   load catalog → register 80            load catalog → register 80
   known banks                           known banks
            │                                     │
   compile() emits RequiredSample{bank,name,variant}
            │                                     │
   bank in catalog? → build raw URL      bank in catalog? → local cache?
   → fetch (IndexedDB cache)               yes → file://   no → raw URL
            │                                     │
            ▼                                     ▼
        decode + register in SampleBank ; soft-fail on error
```

### 4.2 Combined catalog format

A single committed file: `web/static/samples/tidal-drum-machines/catalog.json`.

```json
{
  "_source": "github:geikha/tidal-drum-machines",
  "_commit": "abc123def456…",
  "_generated": "2026-05-21",
  "_base": "https://raw.githubusercontent.com/geikha/tidal-drum-machines/abc123def456…/machines/",
  "banks": {
    "RolandTR808": {
      "_path": "RolandTR808/",
      "bd": ["rolandtr808-bd/RolandTR808-BD.wav", "rolandtr808-bd/RolandTR808-BD2.wav"],
      "sd": ["rolandtr808-sd/RolandTR808-SD.wav"],
      "hh": ["rolandtr808-hh/RolandTR808-HH.wav"]
    },
    "RolandTR909": { "_path": "RolandTR909/", "bd": ["…"], "...": [] }
  }
}
```

- Full sample URL = `_base` + `<bank>._path` + `<file>`.
- `_commit` pins audio URLs to an immutable SHA — upstream churn cannot break already-cached or live URLs.
- Sound codes (`bd`, `sd`, `hh`, `oh`, `cp`, `perc`, …) are whatever sub-folder suffix appears upstream; variant arrays are filenames sorted lexicographically.
- This is the single source of truth. `web/static/` is the canonical location because the CLI already walks up the tree for `web/static/samples/…` (see `find_default_bank_uri`, §4.5) — no copy step or symlink needed.

### 4.3 Catalog generator — `scripts/generate-tdm-catalog.sh`

Bash, alongside `scripts/bump-version.sh`. Run manually when the upstream repo should be refreshed.

1. Shallow `git clone --depth 1 https://github.com/geikha/tidal-drum-machines` into a temp dir.
2. `git rev-parse HEAD` → `_commit`.
3. For each dir in `machines/*/` → one bank, name = dir name.
4. For each sub-folder, sound code = sub-folder name with the leading `<machine-lowercased>-` prefix stripped (fallback: full sub-folder name if the prefix does not match).
5. List `*.wav` (case-insensitive), sort, → variant array. Skip empty sounds.
6. Emit `catalog.json` to `web/static/samples/tidal-drum-machines/catalog.json`.
7. Remove the temp clone.

The script prints a summary (machines, sounds, total files) and is idempotent.

### 4.4 Web host changes

- **New `web/src/lib/audio/bank-catalog.ts`** — fetches `/samples/tidal-drum-machines/catalog.json` once at startup; exposes the parsed catalog and a `resolveCatalogSample(bank, name, variant) → url | null` helper.
- **`bank-registry.ts`** — register the 80 catalog banks as *known/lazy* `BankManifest`s (metadata only, no samples fetched). `loadBank`/`StrudelManifest` types are reused; the catalog bank's per-sample resolution defers to `bank-catalog.ts`.
- **`audio.svelte.ts`** — in the required-sample resolution path (`ensureBankSampleLoaded` / `loadAsset`), when a `RequiredSample.bank` matches a catalog bank, resolve the GitHub raw URL and fetch through the existing `FileLoader` → `UriResolver` (`https` handler, IndexedDB cache). On fetch failure: log a warning, mark that sample missing, continue (do **not** reject `compile()`).
- **Files panel** — new `DrumMachineCatalog.svelte` section inside `FilesPanel.svelte`: search/filter list of machines from the catalog, per-machine "Load" → prefetch all of that machine's samples (pinned cache entries).

### 4.5 CLI host changes

- **`asset_loader.cpp`** — add `find_tdm_catalog_path()` mirroring `find_default_bank_uri()` (env override `NKIDO_TDM_CATALOG`, compile-time macro, walk-up for `web/static/samples/tidal-drum-machines/catalog.json`, install-relative `../share/nkido/`). Add a parser for the combined catalog format.
- **`program_loader.cpp`** — at asset-prep time, load the catalog and register all 80 banks as known. When resolving a `RequiredSample` whose bank is a catalog bank:
  1. If `~/.cache/nkido/tidal-drum-machines/<Machine>/<file>` exists → resolve to `file://`.
  2. Else → resolve to the pinned `raw.githubusercontent.com` URL.
  3. On fetch/decode failure → warn, skip, continue (soft fail).
- The cache dir honors `XDG_CACHE_HOME`; default `~/.cache/nkido/tidal-drum-machines/`.

### 4.6 CLI download script — `scripts/download-tdm.sh`

Bash. Args: one or more machine names, or `--all`.

1. Locate `catalog.json` (same walk-up as the CLI).
2. For each requested machine, read its file list from the catalog.
3. `curl`/`wget` each file from the pinned raw URL into `~/.cache/nkido/tidal-drum-machines/<Machine>/…`, preserving the relative path the catalog encodes.
4. Skip files already present; print a per-machine progress/summary line.

### 4.7 Soft-fail behavior

A required sample that never registers must not crash the VM. `op_sample_play` already plays silence for an unknown numeric sample ID; the host-side bytecode patcher must assign such samples a sentinel/invalid ID rather than aborting. Phase 2 verifies this end-to-end.

## 7. Implementation Phases

### Phase 1 — Catalog generator (½ day)

**Goal:** A reproducible script that produces `catalog.json`.

- Write `scripts/generate-tdm-catalog.sh`; run it; commit `catalog.json`.

**Verification:** Catalog has ~80 banks; spot-check `RolandTR808`/`RolandTR909` sounds and variant counts against the GitHub repo; `_commit` is a real SHA; every URL built from `_base` returns 200.

### Phase 2 — CLI auto-resolve (1 day)

**Goal:** `nkido-cli` resolves catalog banks from GitHub.

- `find_tdm_catalog_path()` + catalog parser in `asset_loader.cpp`.
- Register catalog banks in `program_loader.cpp`; resolve to pinned raw URLs; soft-fail.

**Verification:** `nkido-cli render` a program using `.bank("RolandTR808")` produces audible TR-808 hits; a deliberately bad URL warns and yields silence without aborting.

### Phase 3 — CLI download script + local cache (½ day)

**Goal:** Offline CLI use.

- `scripts/download-tdm.sh`; local-cache lookup in `program_loader.cpp`.

**Verification:** Download `RolandTR808`; render the Phase-2 program with networking disabled — TR-808 still plays from cache; a non-downloaded machine still falls back to GitHub when online.

### Phase 4 — Web runtime resolution (1 day)

**Goal:** `.bank()` auto-resolves in the browser.

- `bank-catalog.ts`; register banks in `bank-registry.ts`; resolution + soft-fail in `audio.svelte.ts`.

**Verification:** In `bun run dev`, a program with `.bank("RolandTR909")` plays; samples appear in the IndexedDB cache; a forced offline fetch warns and continues; no tidal audio is in `web/build/`.

### Phase 5 — Files-panel catalog browser (1 day)

**Goal:** Browse + load the 80 machines.

- `DrumMachineCatalog.svelte`; mount in `FilesPanel.svelte`; "Load" = prefetch.

**Verification:** Search filters the list; sounds/variant counts match the catalog; "Load" prefetches a machine and it then plays offline.

### Phase 6 — Docs (¼ day)

Update `docs/uri-schemes.md` / `docs/sampler_usage.md` with `.bank("<Machine>")` usage, the catalog, and `download-tdm.sh`.

## 8. Edge Cases

| Situation | Expected behavior |
|---|---|
| `.bank("RolandTR808")` | Auto-resolves from the catalog; samples stream on demand |
| `.bank("Nonexistent")` | Not in catalog → existing unknown-bank behavior, unchanged by this PRD |
| `pat("bd")` with no `.bank()` | Default `bpb_808_clean`, unchanged |
| Sample fetch fails (offline / GitHub down / 404) | Warn, that sample is silent, rest of program keeps running |
| Variant index out of range (`bd:99`) | Existing variant-wrap behavior, unchanged |
| Upstream repo updated | Old pinned URLs still work; rerun the generator to adopt new content (new SHA) |
| Catalog bank sound + same drum name as default kit | `.bank()` qualifier disambiguates; no collision |
| CLI cache partially populated | Per-bank decision: downloaded machines use `file://`, others fetch from GitHub |
| Upstream sub-folder not matching `<machine>-<type>` | Generator falls back to the full sub-folder name as the sound code |
| Empty sound sub-folder upstream | Omitted from the catalog |
| `catalog.json` missing at CLI runtime | Catalog banks unavailable; `.bank()` falls back to unknown-bank behavior; a one-line info diagnostic |

## 9. Testing / Verification Strategy

### 9.1 Generator

- Run `generate-tdm-catalog.sh`; assert ~80 banks, non-empty sound arrays, valid SHA.
- Sample 5 random URLs built from the catalog → all return HTTP 200.

### 9.2 CLI (C++ / `nkido-cli`)

- Unit test: catalog parser produces the expected bank/sound/variant structure from a small fixture catalog.
- Integration: `nkido-cli render` a `.bank("RolandTR808")` program ≥ 30 s → non-silent WAV with audible 808 hits.
- Soft-fail: point one sample at a 404 URL → diagnostic warning, program completes, that voice is silent.
- Offline: `download-tdm.sh RolandTR808`, disable network, render again → still plays from `~/.cache/nkido/`.

### 9.3 Web

- `bun run check` passes with the new TS modules.
- Manual: `.bank("RolandTR909")` plays; DevTools → IndexedDB shows cached entries under the GitHub raw URLs.
- Manual: throttle to offline before first fetch → console warning, program keeps running, no crash.
- Build check: `bun run build` → `grep -r tidal web/build/` finds **no** `.wav` files (only the catalog JSON, if served from static).

### 9.4 Manual / listening

- Render a 4-machine groove (808 kick, 909 hat, LinnDrum snare, DMX clap) and confirm each machine sounds distinct and correct.
